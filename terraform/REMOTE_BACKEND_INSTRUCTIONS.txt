Terraform Remote Backend Implementation Guide (Azure Blob Storage)
=================================================================

Goal
----
Move Terraform state from local files to Azure Blob Storage so state is shared, protected, and locked during apply.

Why this matters
----------------
1) Team safety: prevents two people from overwriting local state.
2) Better security: avoids accidental commit of local state files.
3) Reliability: state survives machine loss and supports CI/CD.


What files will change
----------------------
1) New file to add:
   - backend.hcl.example

2) Existing file to update:
   - README.md (inside terraform directory)

3) Optional (already correct in this repo):
   - .gitignore should contain:
     - terraform.tfvars
     - *.tfstate
     - .terraform/


Step 1: Create backend storage resources (one-time)
---------------------------------------------------
Run these commands once in Azure CLI.

Replace values first:
- <BACKEND_RG>           Example: rg-tfstate-prod
- <BACKEND_LOCATION>     Example: southeastasia
- <BACKEND_STORAGE_NAME> Must be globally unique, 3-24 chars, lowercase only
- <BACKEND_CONTAINER>    Example: tfstate

Commands:

az group create \
  --name <BACKEND_RG> \
  --location <BACKEND_LOCATION>

az storage account create \
  --name <BACKEND_STORAGE_NAME> \
  --resource-group <BACKEND_RG> \
  --location <BACKEND_LOCATION> \
  --sku Standard_LRS \
  --kind StorageV2 \
  --min-tls-version TLS1_2

az storage container create \
  --name <BACKEND_CONTAINER> \
  --account-name <BACKEND_STORAGE_NAME>


Step 2: Add backend block in Terraform code
-------------------------------------------
Add this block inside terraform { } in main.tf.

terraform {
  required_version = ">= 1.5.0"

  backend "azurerm" {}

  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 4.74"
    }
  }
}

Notes:
- Keep backend block empty in code.
- Pass actual backend values from backend.hcl so secrets/identifiers are not hardcoded.


Step 3: Add backend.hcl.example
-------------------------------
Create backend.hcl.example in terraform/:

resource_group_name  = "<BACKEND_RG>"
storage_account_name = "<BACKEND_STORAGE_NAME>"
container_name       = "<BACKEND_CONTAINER>"
key                  = "prod.terraform.tfstate"

How to use it:
1) Copy backend.hcl.example -> backend.hcl
2) Replace placeholders in backend.hcl
3) Never commit backend.hcl if you add environment-specific details


Step 4: Initialize backend and migrate state
--------------------------------------------
From terraform/ directory:

terraform init -backend-config=backend.hcl -reconfigure

If you already have local state, Terraform will ask to migrate it.
Answer yes.

Validate:
terraform state list


Step 5: Recommended key naming for environments
------------------------------------------------
Use different key per environment to avoid collisions:
- dev.terraform.tfstate
- staging.terraform.tfstate
- prod.terraform.tfstate

Example backend.hcl per env:
key = "dev.terraform.tfstate"


Step 6: CI/CD recommendation
----------------------------
In pipeline, run init with backend config values from secure variables:

terraform init \
  -backend-config="resource_group_name=$(TF_BACKEND_RG)" \
  -backend-config="storage_account_name=$(TF_BACKEND_STORAGE)" \
  -backend-config="container_name=$(TF_BACKEND_CONTAINER)" \
  -backend-config="key=$(TF_BACKEND_KEY)" \
  -reconfigure

Do not store secrets in repo.


Troubleshooting
---------------
1) Error: Backend initialization required
   - Run: terraform init -backend-config=backend.hcl -reconfigure

2) Error: Storage account/container not found
   - Verify names and subscription:
     az account show
     az storage account show -n <BACKEND_STORAGE_NAME> -g <BACKEND_RG>

3) Error: Authentication failed
   - Run az login and verify the active subscription matches deployment target.


Beginner scenario example
-------------------------
Scenario:
Alice and Bob both work on the same Terraform project.

Without remote backend:
- Alice applies infra and updates her local terraform.tfstate.
- Bob still has old local state and applies changes.
- Resources drift or conflict because Bob's state is outdated.

With remote backend:
- State is in one shared blob.
- Bob always reads latest state during init/plan/apply.
- State locking prevents apply collision.
